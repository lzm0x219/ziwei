# Zig 开发

修改 Zig 源码、公开 API、构建配置或验证流程时，遵循本文件。

## 项目边界

- `src/root.zig` 是公开模块入口。需要对外公开的导出统一由此文件提供。
- 占位函数体不构成领域规范；实现之前先查明适用的标准或已确认决策。
- `src/primitive.zig` 中的基础领域类型当前仍是临时边界。提取到公共库应作为独立变更，并先取得明确确认。
- 保持 `build.zig.zon` 中的包身份不变；常规维护不得修改 `.fingerprint`。
- 将公开 API 变更视为兼容性变更：审慎更新 `src/root.zig`，并为导出行为补充测试覆盖。

## 工具链

使用 `mise.toml` 固定的项目本地工具。通过 `mise exec --` 运行项目命令；仅在固定版本的工具尚未安装时执行 `mise install`。

## 测试规范

- 单元测试写在被验证实现所属的 Zig 源文件中，与实现共同维护。
- 新增或修改公开行为时，通过 `src/root.zig` 验证调用者可见的接口。
- 修复缺陷时，添加能够在修复前失败的回归测试。
- 实现领域规则时，使用表驱动测试覆盖已确认的正常、边界和无效输入；测试名称表达业务规则，而不是实现步骤。
- 领域测试数据记录来源、适用流派和预期结果。尚未确认的语义不写入测试。
- `build.zig` 的 `test` 步骤以公开模块为测试根；仅通过编译且没有执行断言，不构成行为验证。

## 完成门槛

完成 Zig 或构建系统变更前，运行所有适用的验证命令：

```sh
mise exec -- zig fmt --check build.zig build.zig.zon src
mise exec -- zig build
mise exec -- zig build test
```

`lefthook` 会在提交前格式化已暂存的 Zig 文件并运行 `zig build test`，但不能替代明确的最终验证。

只有当 diff 符合请求范围且所有适用的验证均通过时，变更才算完成。验证被跳过或受阻时，报告确切原因。
