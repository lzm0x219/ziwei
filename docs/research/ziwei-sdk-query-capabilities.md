# 紫微斗数 SDK 查询能力研究

- 调研日期：2026-08-07
- 用途：为 `ziwei_query` 的能力分层提供外部参照
- 状态：外部能力快照，不代表本仓库已经确定的公开 API

> [!NOTE]
> 本文只核对官方文档、官方仓库 README 和源码。重点是其他 SDK 实际允许用户问什么，不照搬它们的对象模型、字符串参数或链式 API。
>
> 本仓库据此确认按命盘 scope 分层查询，见 [ADR-0012](../adr/0012-query-layers-by-chart-scope.md)。

---

## 1. 结论

已核验的 SDK 主要提供三类查询：

1. **找事实**：某个宫在哪里、某颗星落在哪个宫、它的对宫或三方四正是什么。
2. **判断关系或条件**：某宫有没有全部／任意／某些星，某星有没有四化，某宫是否向另一宫飞化或发生自化。
3. **选定时间上下文再查询**：给一个日期，得到当时的大限、小限、流年、流月、流日、流时，再查询该层的宫名叠落、流曜、四化和三方四正。

这里最重要的行业惯例不是“按大限索引取数组”，而是：

```text
本命盘
  ├─ 直接导航：宫、星、三方四正、四化关系
  └─ 给定一个时间点 → 得到运限上下文 → 在该上下文中继续查宫、星、四化
```

在已核验的公开接口中，没有看到把“年龄范围／年份范围查询”“排序分页”或“通用查询语言”作为基础能力。常见入口都是**单个宫、单颗星或单个时间点**。

## 2. 排盘构造不等于查询

所有参照库都先构造一张命盘，再围绕命盘查询：

| 属于排盘构造 | 属于查询 |
| --- | --- |
| 输入阳历／农历生日、时辰、性别 | 从现有命盘找宫、找星 |
| 历法转换、闰月处理、排盘流派配置 | 判断宫内有没有星或四化 |
| 安宫、安星、生成本命盘 | 给定目标日期取得运限上下文 |
| 生成运限所需的完整计算事实 | 在某一运限层查询宫名叠落、流曜和四化 |

`ziwei_query` 因而不应接管出生输入、历法换算或重新排盘；它应消费已经构造并验证的领域事实。

## 3. iztro

`iztro` 是本次最完整的一手参照。官方文档把构造命盘、查询本命盘和查询运限明确区分开来：[`bySolar` / `byLunar` 构造星盘](https://iztro.com/posts/astrolabe)、[星盘查询](https://iztro.com/posts/astrolabe)、[宫位查询](https://iztro.com/posts/palace)、[星曜查询](https://iztro.com/posts/star)、[运限查询](https://iztro.com/posts/horoscope)。

### 3.1 用户能问的本命问题

| 大白话问题 | 已核验能力 |
| --- | --- |
| “命宫／夫妻宫在哪里？” | 按宫名或宫位索引取得宫位。 |
| “紫微星在哪个宫？” | 按星名取得星曜，再导航到所在宫。 |
| “这颗星的对宫和三方四正是什么？” | 星曜可导航到对宫及三方四正。 |
| “命宫里同时有紫微和右弼吗？” | 宫位支持“全部都有”。 |
| “这个宫有武曲、贪狼中的任意一颗吗？” | 宫位支持“任意一个”。 |
| “这个宫完全没有地空、地劫吗？” | 宫位支持“全部没有”。 |
| “这个宫是空宫吗？” | 宫位支持空宫判断，并可排除指定星曜。 |
| “这颗星是庙旺吗？有没有化禄／权／科／忌？” | 星曜支持亮度和四化判断。 |
| “命宫化忌有没有飞到兄弟宫？” | 宫位支持源宫到目标宫的飞化判断。 |
| “这个宫有没有自化？自化到哪里？” | 宫位支持自化判断和四化落宫导航。 |

这些不是一个通用筛选 DSL，而是挂在“星盘 → 宫／星／三方四正”上的领域操作。完整公开方法可见 [`FunctionalPalace`](https://iztro.com/posts/palace)、[`FunctionalStar`](https://iztro.com/posts/star) 和 [`FunctionalAstrolabe`](https://iztro.com/posts/astrolabe)。

### 3.2 用户能问的运限问题

`horoscope(date, timeIndex)` 接受一个目标日期和时辰，返回该时间点的完整运限对象；它包含大限、小限、流年、流月、流日和流时，而不是只返回“大限索引”。官方类型还同时给出虚岁、各层宫位索引、宫名序列、四化和部分流曜：[运限类型定义](https://docs.iztro.com/type-definition)、[`horoscope()`](https://iztro.com/posts/astrolabe)。

| 大白话问题 | 已核验能力 |
| --- | --- |
| “2026 年某一天走到哪步大限、哪一个流年／月／日／时？” | 一个目标时间点返回完整运限层级。 |
| “这个时间点的小限落在哪个宫？” | 运限对象可取得小限宫位。 |
| “这步大限的夫妻宫叠到本命哪一宫？” | 按运限层和宫名取得叠落后的宫位。 |
| “流年夫妻宫的三方四正是什么？” | 按运限层查询三方四正。 |
| “这个大限宫里同时有这些流曜吗？任意有一颗吗？全部没有吗？” | 运限宫支持全有／任一／全无判断。 |
| “流年夫妻宫有没有化禄？” | 运限宫支持四化判断。 |

有一个边界值得注意：`Scope` 只把会随层级叠加的星曜范围定义为本命、大限和流年；流月、流日、流时仍存在于运限结果中，但公开的星曜查询范围并没有无限泛化到所有层级。[`Scope` 与 `Horoscope` 类型](https://docs.iztro.com/type-definition)

### 3.3 对设计的启发与不应照搬之处

- 值得借鉴：先定位“用户正在看的盘或运限层”，再在该范围内查宫、星和四化。
- 值得借鉴：“全部有／任意有／全部没有”是反复出现的真实问题。
- 不应照搬：字符串宫名、字符串星名、可空的链式对象图，以及把查询方法分散到每个对象上。
- 不应扩大：iztro 的完整运限计算能力不能成为当前 `ziwei_query` 凭空拥有流月、流日、流时的理由。

## 4. fortel-ziweidoushu

`fortel-ziweidoushu` 是一个独立的中州派 JavaScript 库。仓库当前包版本是 `1.3.4`，具备测试和已发布包，但生态规模仍小，适合作为第二份设计证据，不应当作行业标准：[官方仓库](https://github.com/airicyu/fortel-ziweidoushu)、[`package.json`](https://github.com/airicyu/fortel-ziweidoushu/blob/main/package.json)。

### 4.1 用户能问的问题

| 大白话问题 | 已核验能力 |
| --- | --- |
| “命宫、夫妻宫在哪一格？” | 按宫名或地支找宫格。 |
| “紫微星在哪个宫？” | 按星曜反查宫格。 |
| “兄弟宫是不是同时有太阳、地劫、寡宿？” | 条件查询支持“全部有”。 |
| “夫妻宫只要有武曲或贪狼其中一颗就算符合吗？” | 条件查询支持“任意有”。 |
| “本宫／对宫／三方／三方四正有没有或没有这些星？” | 条件可限定关系范围并做肯定或否定判断。 |
| “虚岁 35 时大限落在哪一格、宫干是什么？” | 能按年龄取得大限宫支和宫干。 |
| “农历某日的大限、流年、流月、流日分别落在哪里？” | 按农历日期取得四层运行上下文。 |
| “每一层有哪些流星和四化？” | 运行上下文包含落宫、流星表和四化表。 |

条件查询源码集中在 [`BoardCriteria`](https://github.com/airicyu/fortel-ziweidoushu/blob/main/src/criteria/boardCriteria.ts)，宫、星、年龄与日期入口集中在 [`DestinyBoard`](https://github.com/airicyu/fortel-ziweidoushu/blob/main/src/model/destinyBoard.ts)；运行上下文的数据形状见 [README 的 Runtime Context](https://github.com/airicyu/fortel-ziweidoushu#runtime-context-大運流年流月流日資訊)。

### 4.2 证据边界

- 按年龄查询只直接返回大限宫支或宫干，不会同时返回完整“大限 + 大限中的具体年份”。
- 日期查询以农历年月日为入口，返回大限、流年、流月和流日，没有公开的流时层。
- 条件是在**一张已经构造的命盘上判断**，不是从大量命盘中搜索。
- 没有看到年龄段、年份段或跨时间层批量筛选接口。
- 它的组合条件能力比 iztro 更像 DSL，但没有证据表明 `ziwei_query` 现在就需要同等抽象。

## 5. 横向归纳：可以怎样用大白话盘点查询功能

### 5.1 找一个确定事实

- “命宫／夫妻宫在哪个地支？”
- “某个地支上是什么本命宫？”
- “紫微星在哪个宫？”
- “生年化禄是哪颗星、落在哪个宫？”

### 5.2 看一组固定关系

- “这个宫的对宫是什么？”
- “这个宫的三方四正是哪四宫？”
- “这颗星的对宫和三方四正是什么？”
- “某宫的化忌飞到哪个宫？”
- “某宫有没有自化？”

### 5.3 判断一个条件

- “这个宫有没有紫微？”
- “这个宫是不是同时有紫微和右弼？”
- “武曲、贪狼是否至少有一颗在这里？”
- “这里是否完全没有地空、地劫？”
- “三方四正里有没有化禄？”

### 5.4 选择一个时间点

- “我虚岁 35 时走哪一步大限？”
- “2026 年走哪一步大限、是这一步的第几年？”
- “某个具体日期对应哪一步大限和哪一个流年？”
- “如果继续支持流月、流日、流时，这个时间点分别落在哪里？”

### 5.5 在运限上下文继续查询

- “这个大限的夫妻宫叠到本命哪个宫？”
- “这个流年的命宫在哪？”
- “这个运限宫里有哪些流曜和四化？”
- “这个运限宫的三方四正是什么？”

## 6. 当前采纳结果

外部 SDK 暴露出的事实查询、条件判断与时间定位能力只是设计输入，不直接决定本仓库的查询层级。经过后续领域设计，本仓库已经确认：

1. L1 本命 scope 同时覆盖已有事实、关系与条件查询，不再局限于单点事实定位。
2. 立极统一任意本命宫起点与大限命宫起点的相对宫名映射，不另建独立的大限宫名叠落机制。
3. L2 表示选定一个大限后的查询 scope，具体能力仍待下一轮设计。
4. 流年及更细层级必须等 `ziwei_core` 拥有相应的完整事实后再决定。
5. 当前仍不设计通用查询语言、任意 predicate、范围查询、排序分页或完整时间线框架。

正式项目决策以 [ADR-0012](../adr/0012-query-layers-by-chart-scope.md)、[ADR-0013](../adr/0013-use-reframe-for-relative-palace-scopes.md) 与 [`ziwei_query` 查询能力设计](../design/ziwei-query.md) 为准。

## 7. 调研限制

- 本文核验的是公开能力和源码形状，没有运行这些库，也不评价其排盘算法正确性。
- iztro 是最完整参照；fortel-ziweidoushu 是小众但可核验的独立实现。其他近期项目多数仍处于 `0.x` 或直接移植 iztro，本次没有把它们凑成“成熟 SDK”样本。
- “未看到某接口”只表示在本次核对的官方文档和公开源码中没有发现，不证明项目内部或未来版本永远不存在。
