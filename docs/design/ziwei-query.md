# `ziwei_query` 查询能力设计

本文记录 `ziwei_query` 已确认的分层、查询能力与接口取舍；完整公共签名由 [`ziwei-query-interface.md`](ziwei-query-interface.md) 统一记录。首批公共面已经实现；条件能力仍按本文件标注的边界继续收敛。

## 包边界

- `ziwei_core` 负责计算并保存不可变领域事实，不承担条件查询、关系导航或分析。
- `ziwei_query` 只读取 `ziwei_core` 的公开事实，不复制、修改或重新计算命盘。
- 依赖方向固定为 `ziwei_query -> ziwei_core`。
- `ziwei` 依赖 `ziwei_core` 与 `ziwei_query`，并作为用户唯一的公开门面。
- `ziwei_query` 首批保持无状态。

## 查询分层

查询按回答问题所需的最小命盘 scope 分层，完整决策见 [ADR 0012](../adr/0012-query-layers-by-chart-scope.md)。只有改变宫位坐标、使十二宫获得一套相对宫名的对象才称为 scope；单纯定位某个时间事实的结果不是 scope。

- L1 本命 scope：查询全部本命事实、导航、关系与条件。
- L2 大限 scope：选择一个大限后，在该大限 scope 中查询。
- 只有 `ziwei_core` 保存了完整的相应事实后，才增加流年、流月等新层级。

大限列表和每个大限已有的十个年份条目属于 `Natal` 的本命事实，因此可以在 L1 查询；选择某个大限作为当前观察范围才进入 L2。

## L1 本命查询

### 整盘查询

- 查询完整出生上下文：性别、可选农历年序号、生年干支、农历月、日、时辰。
- 查询生肖、五行局、命宫、身宫、来因宫与大限方向。
- 查询全部十二宫、十八颗星曜、生年四化、四十八条宫位四化关系。
- 查询全部十二个大限；每个大限包括 `DecadeIndex`、大限命宫地支、起止虚岁，以及十个 `DecadeYear` 的可选农历年序号与虚岁。

### 宫位查询

- 按 `PalaceName` 或 `Branch` 查询唯一宫位；按 `Stem` 查询所有匹配宫位。
- 查命宫、身宫与来因宫实际落在哪个已有宫位。
- 查询宫位的宫名、地支、天干、星曜与四条宫位四化关系。
- 遍历全部十二宫。
- 不使用裸整数索引作为领域查询条件。

### 星曜查询

- 按 `StarName` 查询唯一星曜及其所在宫位。
- 查询星曜的名称、类别、斗系、生年四化与向心／离心自化。
- 遍历当前支持的全部十八颗星曜。
- 不查询内核尚未保存的星曜、亮度或解释文本。

### 四化查询

- 查询全部生年四化，或按 `Transformation` 查询对应星曜与宫位。
- 按源宫、目标宫、目标星曜、四化代码或这些条件的明确组合查询宫位四化关系。
- 查询星曜是否存在向心或离心自化及其四化代码。
- 不做多跳推导、重新计算或命理分析。

### 固定宫位关系

- 立极。
- 叠宫。
- 对宫与六条宫线。
- 三方。
- 河图宫位。
- 四正。
- 暗合宫。

固定关系不包括相邻宫、夹宫、四马地、四败地、四墓地及通用地支刑、害、破。立极与大限 scope 的复用规则见 [ADR 0013](../adr/0013-use-reframe-for-relative-palace-scopes.md)。

立极建立完整的 L1 查询 scope，宫位、星曜、四化、关系和条件查询都可以在其中复用。在该 scope 中按宫名导航时使用相对宫名；宫位原有的本命宫名仍然可查。身宫与来因宫的实际位置不变，同时可以查询它们在当前 scope 中对应的相对宫名。

叠宫支持三种查询：按当前 scope 宫名查询其叠到的本命宫名，按本命宫名反查当前 scope 宫名，以及遍历当前 scope 的全部十二组叠宫关系。三者读取同一份立极映射，不建立额外叠宫数据。

河图宫位按当前 scope 的相对宫名计算，因此任意立极与大限都复用同一套一六共宗关系，不固定指向原本命宫名。它支持按指定宫正查河图宫位、按河图宫位反查来源宫，以及遍历当前 scope 的全部十二组河图关系。

### 条件与组合查询

当前已确认：

- 空宫指没有主星；即使有辅星，仍为空宫。
- 给定一组星曜，可以判断指定宫是否全部都有、至少有一颗或全部没有。
- 同样的条件既可用于判断指定宫，也可用于找出整盘所有符合条件的宫。
- 可以按 `StarCategory` 与 `StarGalaxy` 查询宫内或整盘星曜。
- 同宫指多颗星曜落在同一个宫。
- 会只查看同一三方中的另外两个宫；照只查看对宫，二者不合并。
- 给定多颗星曜，可以判断它们是否同宫；同宫时可以定位所在宫位。
- 对会与照都可以判断关系宫内是否包含全部指定星曜、至少一颗或全部没有；会以两个会宫的星曜并集判断，不要求指定星曜落在同一个会宫，若要求同一宫则使用同宫查询。
- 会与照支持双向查询：既可以从指定宫查询关系宫内的星曜，也可以从指定星曜反查与其所在宫形成会或照关系的宫位。
- 四化条件必须明确区分生年四化、宫位飞化与星曜自化，不提供含义混杂的“某宫有某化”判断。
- 宫位飞化支持双向查询：既可以从源宫查询四化飞往的目标宫与星曜，也可以从目标宫或星曜反查来源宫。
- 可以查询指定宫会到的生年四化，以及对宫形成的生年四化关系；对宫的生年忌称冲，禄、权、科称照。
- 自化条件同时支持方向与四化代码，可以从宫或星曜判断，也可以反查整盘符合条件的星曜。
- 没有借宫概念，不判断命理格局。

条件与组合查询仍在设计中，尚未封口。

## L2 大限查询

L2 宫位查询先选中一个大限，再以其大限命宫为起点建立 `DecadeScope`，并复用全部 L1 查询能力。大限或限内年份可以通过三种领域事实定位：

- `Query::decade(DecadeIndex)` 明确指定第几步大限，直接得到 `DecadeScope`。
- `Query::decade_year_at_age(age)` 按虚岁定位所属 `Decade` 与对应 `DecadeYear`；十二个大限始终保存完整虚岁范围，因此始终可用。
- `Query::decade_year_at_lunar_year(year)` 按农历年序号定位所属 `Decade` 与对应 `DecadeYear`；只有 `NatalContext.year` 存在、全部 `DecadeYear.year` 均可用时才能查询。

三种定位方式最终关联同一个 `DecadeScope`，不代表实现优先级，也不产生不同的大限查询模型。后两种方式先得到 `DecadeYearSelection`，需要通过 `decade()` 回到其所属的 `DecadeScope` 后再进行宫位、星曜、四化、关系或条件查询。

按虚岁或农历年序号定位得到的 `DecadeYearSelection` 同时关联所属 `DecadeScope`，并包含对应的 `DecadeYear` 及其在该大限十年中的 `DecadeYearOrdinal`；结果包含虚岁，并在绝对年份事实存在时包含农历年序号。选中一个大限后，也可以通过 `DecadeScope::year(DecadeYearOrdinal)` 按本限第 `1..=10` 年直接得到对应的 `DecadeYearSelection`。`DecadeYearOrdinal` 是领域中的一基有效序号。只按 `DecadeIndex` 选择时不额外选中某个 `DecadeYear`。

`DecadeYearSelection` 只是 L2 中被定位的时间事实，不改变宫位坐标，因此不是 scope，也不直接提供 L1 查询方法；它不产生流年宫名、流年星曜、流年四化或独立流年 scope。

选中一个大限后，可以查询上一大限与下一大限；第一大限没有上一限，最后一限没有下一限，导航不循环回绕。

通过虚岁、农历年或限内序号得到 `DecadeYearSelection` 后，可以查询上一年与下一年。导航跨越大限边界时，结果关联相邻大限；十二大限的第一年与最后一年没有越界结果，且导航不产生流年 scope。

L2 四化查询先以大限相对宫名定位实际宫位，读取该宫已有的宫干四化关系，再把目标实际宫位解析为大限 scope 的相对宫名。生年四化与星曜自化同样保持原事实；每个大限都不产生或重算新的四化与边集。

L2 星曜查询先以大限相对宫名定位实际本命宫，再读取该宫原有的星曜。星曜不移动，也不产生大限星曜或额外流曜；空宫、同宫、会、照与冲等条件都在大限相对宫名关系下观察这些原有事实。

除查询一个已选中的大限外，L2 还可以对固定十二个大限逐一建立相同 scope、应用同一个 L1 条件并返回全部匹配项，例如查找命宫有指定星曜、夫妻宫为空宫或生年忌冲命宫的所有大限。匹配结果始终保持大限的自然先后顺序，不提供自定义排序。这是 L2 跨 scope 条件查询，不引入年龄／年份范围、排序分页或完整时间线框架。

## 接口方向

公开 interface 采用借用式导航结构：先选择会改变宫位坐标的 scope，或定位不改变坐标的时间事实，再查询对象。

- 用户通过 `ziwei::query(&Natal)` 进入；`ziwei` 将稳定查询类型选择性重导出到根路径，普通用户不直接依赖 `ziwei_query`。
- `Query` 选择本命或大限，也可以按虚岁或农历年定位 `DecadeYearSelection`；任意立极由 `ScopedPalace::reframe()` 进入。
- 本命与任意立极使用 `ReframeScope`；`DecadeScope` 直接提供相同的 L1 查询方法并增加大限能力。只有这两类对象承载立极查询。
- `DecadeYearSelection` 只提供选中的 `DecadeYear`、`DecadeYearOrdinal`、所属 `DecadeScope` 及前后年份导航；需要调用 `decade()` 后才能进行 L1 查询。
- `ScopedPalace`、`ScopedStar` 与 `ScopedPalaceTransformation` 同时保留当前立极解释和底层 `fact()`，不重复 core 的静态 getter。
- 所有查询对象只借用同一个不可变 `Natal`，是轻量 `Clone + Copy + Debug + PartialEq + Eq` 句柄；相等比较遵循不可变命盘事实与 scope 的值语义，不复制、修改或重新计算事实。
- 固定集合使用无额外分配的稳定顺序迭代器；反查与跨十二大限筛选复用标准 `filter`，不建立 `Condition`、operation 或查询 DSL。
- 确定存在的结果直接返回，正常缺省使用 `Option`，范围输入失败使用精确 `Result`；不定义总 `QueryError`。
- `ReframeScope` 的立极查询方法保持单一内部声明源，并由 `DecadeScope` 提供同名 inherent methods；不手写重复委托，也不使用 `Deref` 模拟继承。当前实现以私有 `Scope` 统一语义，并由同一宏生成两类 scope 的 inherent methods；`DecadeYearSelection` 不参与。

完整且唯一的公共签名、返回形状、错误与顺序契约见 [`ziwei-query-interface.md`](ziwei-query-interface.md)。本文只保留能力语义和 interface 取舍，不重复签名清单。

## 仍不进入公共契约

- `ziwei_query` 内部模块、私有字段与索引表示。
- `const`、内联等微观优化。
- 通用查询语言、任意布尔表达式、排序或分页框架。
- 排盘、历法换算、解释、断语及命理格局判断。
