# 领域语义收口

> 状态：已确认（2026-08-05）
>
> 目标：在迁移 `ziwei_core` 前，使现有 Rust 实现与已确认的领域文档一致。
>
> 本文只确定语义和执行顺序，不设计新的结构体或查询 interface。

## 收口范围

本阶段只处理已确认但尚未落实的领域语义：

- 去掉大限、流年额外四化及其计算路径；
- 将来因宫作为排盘时确定的固定叠落事实；
- 将自化随宫干飞化关系保存；
- 保持本命、大限和流年视图只负责宫职叠落。

暂不迁移 crate，不设计 `ziwei_query` interface，也不增加历法或分析能力。

## 四化与时间视图

命盘只保存生年四化和本命宫干飞化。大限、流年不会产生另一组四化，也不会重算宫干飞化。

时间视图只改变宫职叠落到哪一地支。查询宫干飞化时，按叠落后的地支读取本命盘中已经保存的边。

现有“任意天干都可生成额外四化”的泛化模型，以及大限、流年四化叠加路径应删除。生年四化继续作为固定命盘事实保留。

## 来因宫与自化

来因宫由生年天干确定，在排盘时保存其叠落地支。查询只读取结果，不重新扫描十二宫。

自化在生成宫干飞化关系时判定，并与关系一同保存。查询层直接读取 `Out`、`In` 或 `None`，不再根据源宫和目标宫临时推导。

## 执行顺序

1. 删除大限、流年额外四化模型、任意天干四化查询和时间视图中的四化叠加路径。
2. 保留并整理生年四化这一固定命盘事实。
3. 在排盘流程中保存来因宫叠落地支和每条宫干飞化关系的自化标注。
4. 调整相关测试与 Rust 文档，删除已经失效的术语和示例。
5. 收口完成后，再开始向 `ziwei_core` 迁移稳定领域类型与排盘实现。

## 验收条件

- 公共接口不再暴露任意天干四化，也不提供大限、流年四化叠加能力；
- 大限、流年视图不生成任何额外四化或宫干飞化关系；
- 生年四化、来因宫和宫干飞化在视图切换前后保持不变；
- 自化标注随宫干飞化关系保存，查询不做二次判断；
- workspace 持续编译，现有 Rust 测试通过。

## 后续

本阶段已经完成，现有实现也已按 [`ziwei_core` 首批迁移](ziwei-core-first-batch.md)整体迁入 core。下一步执行 [#280](https://github.com/matharts/ziwei/issues/280)，围绕不可变 `Ziwei` 重写 `ziwei_core`；`ziwei_query` 的 interface 继续延后，直到 `Ziwei` 数据模型稳定。
